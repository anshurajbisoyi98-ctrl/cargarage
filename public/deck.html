1968 MUSTANG FASTBACK

🏎️ The Engineering Vision

A unified digital platform connecting classic automotive collectors with certified restoration workshop facilities.

  • Interactive Visual Engine: Single-entry 4-phase loading timer with physics-eased grand reveal settling permanently on Chapter 3.
  • Enterprise Service Concierge: Complete fleet management, appointments, 5-stage Kanban stepper, and certified legal invoicing.

  • Backend: Node.js, Express 5 REST API, Cookie-Parser, In-Memory Rate Limiting.

Problem & Solution

THE AUTOMOTIVE CHALLENGE

Why classic vehicle owners need an integrated digital platform

🔴 Friction Points in Classic Ownership

  • Unverified Provenance: Service records scattered across loose paper receipts; high vulnerability to odometer rollback and falsified logs.
  • Disjointed Software: Dealer management systems are clunky and dated, while marketing websites are completely static brochures.
  • Zero Proactive Telemetry: Owners miss critical maintenance milestones due to lack of time and mileage baseline calculations.
  • No Role Isolation: Lack of clean boundary between customer self-service and master technician dispatch bays.

🟢 The Master Concierge Solution

  • Immutable Service Logbook: Invoices (INV-YYYY-XXXX) snapshot parts and labor costs atomically in database transactions.
  • Physics-Eased Cinematic Showcase: WebGL layer blending that presents the vehicle in slow-motion and settles on fine details.
  • Smart Maintenance Engine: Auto-computes service due dates (+6 months) and mileage thresholds (+5,000 km) with snooze support.
  • Strict Dual-Persona Architecture: Customers manage garage fleet; administrators dispatch technicians across Kanban stages.

Security & RBAC

STRICT ROLE ISOLATION

Preventing unauthorized customer-to-admin privilege escalation

👤 Customer Account (isAdmin: false)

  • No Role Switcher: The [ Customer ] | [ Admin ] toggle is completely hidden; displays static 👤 Customer badge.
  • 6 Client Tabs Only: My Garage, Book Service, Service History, Reminders, Report Problem, Profile.
  • Public Registration Guard: Public signup endpoint explicitly hardcodes isAdmin: false, ignoring client payload.
  • Zero Cross-Tenant Access: Blocked from viewing other owners' vehicles or administrative endpoints.

🛡️ Administrator Account (isAdmin: true)

  • Full Control Bay: Overview telemetry, Requests queue, Active Kanban stepper, Certified Records, Analytics, Centers, Users, Heritage, Problems.
  • Role Switcher Enabled: Only registered administrators see the toggle to inspect customer perspective.
  • Cryptographic Verification: Server verifies req.user.isAdmin via JWT payload signature on every sensitive route.
  • CLI Provisioning Only: Admin accounts can only be provisioned through our offline server CLI script (create-admin.mjs).

CERTIFIED INVOICING & TRANSACTIONS

Multi-document ACID guarantees for financial and odometer integrity

🔒 Multi-Document ACID Transaction

await mongoose.connection.transaction(async session => {
  // 1. Lock & complete service request
  const request = await ServiceRequest.findOneAndUpdate(
    { _id: id, status: { $in: ['accepted', 'in_progress'] } },
    { $set: { status: 'completed', currentStage: 'completed' } },
    { session, new: true }
  );

  // 2. Validate & advance vehicle mileage
  const vehicle = await Vehicle.findById(request.vehicle).session(session);
  if (mileage < vehicle.mileage) fail(400, 'Mileage cannot decrease.');
  vehicle.mileage = mileage;
  await vehicle.save({ session });

  // 3. Snapshot parts & labor into invoice
  record = (await ServiceRecord.create([{ ... }], { session }))[0];
});

Security Hardening

ENTERPRISE RESILIENCE

Neutralizing XSS, CSRF, brute-force attacks and database leakage

🛡️ Defense Layers

  • XSS Immunity: JWT is stored in an httpOnly, SameSite: Strict cookie. Browser JavaScript cannot access it via document.cookie.
  • Anti-CSRF Origin Guard: Validates incoming request Origin against whitelist (APP_ORIGIN) and enforces application/json.
  • Sliding-Window Rate Limiter: In-memory tracker restricts login and registration attempts to 30 requests per 15 minutes.
  • Centralized Error Masker: Maps low-level database errors (code 11000, CastErrors) to clean status codes without leaking stack traces.

Examination Defense

MENTOR DEFENSE Q&A

Authoritative engineering answers for panel evaluation

Q1: Why httpOnly cookies instead of localStorage?

Answer: localStorage is vulnerable to Cross-Site Scripting (XSS). Any third-party script can steal tokens. An httpOnly, SameSite: Strict cookie is completely inaccessible to JavaScript, guaranteeing XSS immunity while preventing CSRF.

Q2: How do you prevent cross-tenant data tampering?

Answer: Our centralized ownedVehicle(vehicleId, user) middleware validates String(vehicle.owner) === String(user._id). Unauthorized requests throw an immediate 403 Forbidden at the database layer.

Q3: What happens if a network crash occurs during invoicing?

Answer: Invoicing runs inside a MongoDB ACID transaction. Odometer update, request completion, and invoice creation commit together. Any failure triggers an automatic rollback with zero orphaned records.

Q4: How does the timer ensure single-entry execution?

Answer: The loading sequence is executed during initial asset decoding. Upon 100% completion, .loading.done fades out the element. Because internal navigation runs as an SPA, the timer never re-executes until a browser refresh.
